# Post Tags Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add curated post tags, author-side selection of up to five tags, reusable clickable tag pills, and exact `/blog?tag=<tag>` filtering while preserving existing posts and readers.

**Architecture:** Store tags as an optional, bounded string array directly on each `posts` document. Keep the canonical values and pure validation helpers in a dependency-free shared module consumed by Zod, the create form, and Convex; keep Convex's server-side validation independent of client validation. Because Convex 1.34.0 has no array-membership filter operator, `getPosts` will paginate the newest-first source query and apply `Array.prototype.includes` to each bounded page in JavaScript; the returned cursor remains the cursor for the unfiltered source range. The server-rendered blog list will follow those cursors when a tag filter is active so the first visible filtered page is not falsely empty when early posts do not match.

**Tech Stack:** Next.js 16 App Router Server Components, Convex 1.34.0 queries/mutations and cursor pagination, React Hook Form, Zod 4, TypeScript, Tailwind CSS, existing `PostCard`/`EmptyState` components, and Vitest with edge-runtime and jsdom suites.

## Implementation Decisions

- Use exactly these initial canonical values in `lib/constants/post-tags.ts`: `Technology`, `Design`, `Culture`, `Science`, `Business`, `Music`, `Tutorial`, `Theory`, `Architectural`, `Landscape`, `Photography`, `Software`, `Hardware`, `Camera`, and `Nature`. Keep the exported list as a readonly tuple so both the `PostTag` type and `z.enum` derive from one source.
- Export `MAX_POST_TAGS = 5`, `isCanonicalPostTag(value)`, and `isValidPostTags(tags)` from the shared module. `isValidPostTags` requires 0–5 values, every value to be canonical, and no duplicates. Display code does not reject legacy removed values: old stored strings remain visible as pills, while the Convex filter rejects a removed/unknown query value before returning results.
- Define `postSchema.tags` with the shared tag schema and `.default([])`. The create form's `defaultValues.tags` is also `[]`, so every new client submission includes a canonical array.
- Define `createPost.args.tags` as `v.optional(v.array(v.string()))` for old clients that still omit the argument. Normalize with `const tags = args.tags ?? []`, validate before the insert, and always write `tags` to the new document. The mutation must throw `new ConvexError("Invalid tags")` for invalid membership, duplicates, or more than five values.
- Define `getPosts.args.tag` as `v.optional(v.string())`. If `tag` is present but not in the canonical list, return a completed empty pagination result and never fall back to the unfiltered listing. If it is canonical, paginate the newest-first posts query exactly as today, then use `(post.tags ?? []).includes(args.tag)` on `result.page` before hydration. Without `tag`, retain the current page and ordering unchanged.
- Do not write `q.eq(q.field("tags"), args.tag)`: Convex 1.34.0's `FilterBuilder` has equality/comparison/boolean operators but no array-membership operator, and equality against a string would not match a string array. Convex's official filtering guidance documents JavaScript array filtering for tag membership, while its pagination guidance allows transforming `result.page`; the tradeoff is that a filtered page can contain fewer items than `numItems` and its cursor advances through the source page. See [Convex filtering](https://docs.convex.dev/database/reading-data/filters) and [Convex pagination](https://docs.convex.dev/database/pagination).
- To handle that cursor behavior on `/blog?tag=`, `BlogPostList` will call `getPosts` repeatedly only when a tag is active, append each filtered page, and continue with `continueCursor` until it has 50 matching posts or `isDone` is true. Each request remains bounded at `numItems: 50`; the loop is capped by Convex's source `isDone` result and does not use `collect()`. The unfiltered blog and landing-page calls remain one paginated request.
- Normalize `tags` to `[]` in `getPosts`, `getPostById`, `getPostsByAuthorId`, `getBookmarkedPosts`, and `getFeed` result objects. This keeps legacy documents safe for all shared-card consumers and lets detail/card rendering remain simple.
- Keep tag filtering exact and case-sensitive. The UI only submits canonical values, but a manually typed URL is treated as an unknown tag and returns a completed empty result.
- Keep the existing server/client boundaries: create remains a client form with a mutation; blog and detail remain Server Components; tag pills are Server Components using `next/link`; no new shadcn primitive or tag table is needed.

```ts
export const POST_TAGS = [
  "Technology",
  "Design",
  "Culture",
  "Science",
  "Business",
  "Music",
  "Tutorial",
  "Theory",
  "Architectural",
  "Landscape",
  "Photography",
  "Software",
  "Hardware",
  "Camera",
  "Nature",
] as const;

export type PostTag = (typeof POST_TAGS)[number];
export const MAX_POST_TAGS = 5;

export function isCanonicalPostTag(value: string): value is PostTag {
  return (POST_TAGS as readonly string[]).includes(value);
}

export function isValidPostTags(tags: readonly string[]): boolean {
  return (
    tags.length <= MAX_POST_TAGS &&
    new Set(tags).size === tags.length &&
    tags.every(isCanonicalPostTag)
  );
}
```

Keep this file free of React, Zod, Convex, browser APIs, and Node APIs so the Next and Convex bundlers can share it.
