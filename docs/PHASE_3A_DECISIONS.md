# Phase 3A Decision Log

This log records cross-cutting Phase 3A decisions that future slices must not
silently reverse. Product details live in `docs/PHASE_3A.md`.

## Dashboard access clarification (2026-10-07)

Following the late review of merged PR #96, the maintainer explicitly approved
keeping **Dashboard** (`/dashboard`) in the shared desktop sidebar and mobile
drawer. This amends the navigation restriction associated with 3A-007: access
to the existing Dashboard is approved, but its Overview purpose, composition,
and redesign remain deferred. The authenticated logo still links to Dashboard.
Do not remove the destination merely because the redesign is deferred.

## Documentation governance amendment (2026-10-11)

The maintainer approved revision-based documentation: implementation,
verification, and completion wording ship in the same PR. GitHub owns review
and merge state; no routine merge-record PR is needed. Operational rules live
in [AGENTS.md](../AGENTS.md#documentation) and [the PR workflow](PR_CHECKLIST.md).

This supersedes the **intentionally not gitignored** clause of 3A-017.
Known local-artifact paths, including `docs/superpowers/`, are now ignored and
checked against the Git index locally and in CI. Manual inspection still
covers arbitrary filenames. Artifacts remain local-only, with the archive and
removal lifecycle of 3A-028 unchanged. The earlier choice relied on manual
staging review alone; the extra checks reduce accidental inclusion without
adding dependencies or a paid service.

## Engagement notification amendment (2026-10-26)

This records the maintainer-approved notification iterations after the compact
baseline. It supersedes the publication-notification preservation requirement
and notification-expansion deferral in [the product direction](PHASE_3A.md).
The current scope covers follows, post likes, comments, and comment likes;
publication discovery continues through the reader feed. It adds a drawer that
preserves the source page, direct focused conversation destinations, always
detailed mobile rows, saved desktop expansion, follow-back actions, and
individual/scoped deletion. [Features](../FEATURES.md#notifications) owns the
behavior; [verification](NOTIFICATIONS_EVIDENCE.md#current-revision-summary)
records results and remaining acceptance.

This extends 3A-033's per-row read model: individual row activity marks the row
read, while visiting the list, opening the drawer or row menu, and bulk
expansion do not. The retention amendment in 3A-034 remains unchanged. Email,
push delivery, follower directories, and social activity feeds remain deferred.

## Saved and Liked dashboard amendment (2026-10-26)

The maintainer explicitly moved Saved and Liked into the dashboard while
keeping separate pages and navigation destinations. Saved needs its own page
for future collection organization; that feature is not implemented by this
routing change. This supersedes 3A-008 and the reader-placement part of 3A-018.
Existing Saved/Liked addresses redirect to the corresponding dashboard pages;
they no longer render in the reader shell. [Features](../FEATURES.md#private-collections)
owns current behavior. This does not reopen the deferred Dashboard Overview
redesign or move other reader utilities.

## Saved and Liked time-group presentation amendment (2026-10-27)

The maintainer approved the final collection presentation on top of the separate
dashboard pages. Saved and Liked group posts by relationship time into
collapsible Today, Yesterday, Previous 7 days, Previous 30 days, and Earlier
sections. Groups start expanded and show their currently loaded count; collapse
state is session-scoped per signed-in user and collection. Collection cards omit
a per-post saved/liked timestamp.
Tablet and desktop use 3:2 cards with tags under the cover; phones use flat rows
without tags. Saved exposes only the bookmark action and Liked only the heart
action. Collection search, filters, and exact timestamps remain deferred. This
refines the 2026-10-26 routing amendment and does not change dashboard placement
or reopen the deferred Dashboard Overview redesign.

## Feed and Notifications workspace amendment (2026-10-28)

The maintainer moved the authenticated Feed and Notifications pages into the
workspace shell at `/dashboard/feed` and
`/dashboard/notifications`. Their former `/feed` and
`/notifications` addresses redirect to the workspace routes.
Feed remains the same bounded reader stream. The notifications bell remains a
drawer; the full notification page now opens inside the workspace. This amends
the route placement in the target-state architecture and the page-placement
portion of 3A-010. [Features](../FEATURES.md#notifications) owns behavior.
